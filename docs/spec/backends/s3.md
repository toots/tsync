# Backend driver: `s3` (AWS S3 and S3-compatible services)

How the `s3` driver fulfils [the store contract](../06-backends.md). Everything a bucket answers the same way whoever runs it (capabilities, watch, verify, discard, the server-side function, the job formats) is in [object-store-common.md](object-store-common.md); this file covers only what is S3-specific: the wire, signing, endpoints, error mapping, the service's quirks.

OCaml notes: [../ocaml/backends/s3.md](../ocaml/backends/s3.md).

Code: `lib/backends/drivers/s3/s3_backend.ml` (verbs), `lib/lwt/backends/drivers/s3/s3_backend_lwt.ml` (registration), the pinned client library `aws-s3` (fork `github.com/toots/aws-s3#tsync`, which carries the conditional-write, bigstring-body, key-encoding and connection-pool changes this driver depends on), `lib/local/tls/tls_conf.ml` (TLS backend choice).

---

## 1. Configuration

Backend object in a domain's `backends` array (common keys `type`, `name`, `role`, `link` are the composite's, see [06 §2.5](../06-backends.md)):

| JSON field | Type | Required at runtime | Documented default | Meaning / validation |
|---|---|---|---|---|
| `bucket` | string | yes | — | Bucket name, used verbatim as the first path segment (path-style addressing). |
| `region` | string | **yes** (see §10.1) | `us-east-1` | SigV4 signing region. Without `endpoint` it must be one of the 18 names the client library knows (`us-east-1/2`, `us-west-1/2`, `ca-central-1`, `eu-west-1/2/3`, `eu-central-1`, `sa-east-1`, `ap-northeast-1/2/3`, `ap-southeast-1/2`, `ap-south-1`, `cn-north-1`, `cn-northwest-1`); any other raises `Failure "Unknown region: …"` at store construction. With `endpoint` it is any string (only signed, never parsed). |
| `endpoint` | string | no | `""` = AWS | Bare host name of an S3-compatible service (`s3.us-west-004.backblazeb2.com`, `<account>.r2.cloudflarestorage.com`, `minio.lan`). No scheme, no port, no path: the value becomes both the TCP host and the `Host` header, and the port is always 443. |
| `accessKeyId` | string | yes | — | SigV4 access key. |
| `secretAccessKey` | string, secret | yes | — | SigV4 secret. Masked (`***`) in any rendered config. |
| `unsignedPayload` | bool (`true/1/yes/on`, `false/0/no/off`, JSON bool) | no | `false` | Sign object PUTs with `UNSIGNED-PAYLOAD` instead of the body's SHA-256 (§3.2). Unparseable value → `false`. |
| `shareUrl` | string | no | `""` = no shares | Base URL of the share endpoint deployed beside the bucket (Lambda Function URL or vanity domain). `""` and absent both mean none. |

No session token (`x-amz-security-token`) and no instance-profile / environment credential lookup: static keys only. Unknown keys in the backend object are refused at config parse (the registry's field list is the allow-list).

Construction (`make`): credentials from the two keys; region = `Vendor{region_name = region; host = endpoint; port = None}` when `endpoint` is given, else the AWS region enum; endpoint record = `{inet = IPv4; scheme = https; host; port = 443; region}` where host is `endpoint` or `s3.<region>.amazonaws.com`; a fresh `Health.t`; then wrapped by the object-store shell. Nothing reaches the network at construction.

`tsync config --edit` (wizard) prompts the seven spec fields; "Fill from Terraform" pulls `bucket`, `region` (omitted if empty), `accessKeyId`, `secretAccessKey`, `shareUrl` from `terraform output` (`stores` map and the sensitive `secret_access_keys` map, keyed by store name).

## 2. Addressing and request shape

- **Path-style** always: `https://<host>/<bucket>/<key>` for object ops, `https://<host>/<bucket>?…` for bucket ops. Virtual-hosted style is never used. AWS still serves path-style for existing and new buckets; R2, B2, MinIO accept it.
- **IPv4 only**: the host is resolved with `getaddrinfo(AF_INET)`, first address taken. An IPv6-only network cannot reach the store.
- **HTTP/1.1**, persistent connections (§6). No `Expect: 100-continue`.
- **Key encoding** (path): every byte outside `[A-Za-z0-9_.~-]` and `/` is percent-encoded as `%XX` (uppercase hex), `%` included (`%` → `%25`) and `+` included (`+` → `%2B`). The **same** encoded string is used as the canonical URI in the signature and as the request target on the wire. Both historic bugs were a mismatch between the two: `+` signed as `%2B` but sent raw, `%` signed literally but sent as the escape it resembled; each answered 403 `SignatureDoesNotMatch` on every key holding one. (Keys tsync writes are hex, `-`, `/`, fixed segments, base64url share tokens and user domain names, so only the domain name can carry such characters — which is why the conformance suite still pins them.)
- **Query encoding**: each `k=v` pair percent-encodes everything outside the unreserved set (`/` becomes `%2F`); canonical query = pairs sorted as strings, joined with `&`. Wire query = same pairs in request order.
- Headers sent on every request: `Host`, `x-amz-date` (`YYYYMMDDTHHMMSSZ`, from the local wall clock), `x-amz-content-sha256`, `Authorization`, `User-Agent: aws-s3 ocaml client`; plus `Content-Length` on PUT/POST.

## 3. Authentication: SigV4

### 3.1 Signing

Header-based AWS Signature Version 4, service `s3`, computed per request by the client library:

1. `canonical_request = VERB \n canonical_uri \n canonical_query \n canonical_headers \n signed_headers \n payload_hash`. **Every header sent is signed** (lower-cased names, sorted, `name:value\n`, values untrimmed); `signed_headers` is the `;`-joined names.
2. `scope = <YYYYMMDD>/<region>/s3/aws4_request`; `string_to_sign = "AWS4-HMAC-SHA256\n<date>T<time>Z\n<scope>\n" ^ hex(sha256(canonical_request))`.
3. `signing_key = HMAC(HMAC(HMAC(HMAC("AWS4"^secret, date), region), "s3"), "aws4_request")`, cached per (access key, region) and recomputed when the date changes.
4. `Authorization: AWS4-HMAC-SHA256 Credential=<akid>/<scope>,SignedHeaders=<…>,Signature=<hex hmac>`.

Clock skew: the date is the local wall clock at request build time; S3 refuses a request more than 15 minutes off (`RequestTimeTooSkewed`, 403 → Permanent). A retry rebuilds and re-signs, so a retried request is never stale by the ladder's own delays.

### 3.2 Payload hash and `unsignedPayload`

| Request | `x-amz-content-sha256` |
|---|---|
| GET, HEAD, DELETE, list | `hex(sha256(""))` |
| Object PUT, `unsignedPayload = false` | `hex(sha256(body))` — a full pass over the body (8 MiB for a chunk) before the first byte is sent, redone on every retry |
| Object PUT, `unsignedPayload = true` | `UNSIGNED-PAYLOAD` |
| Bulk-delete POST | always `hex(sha256(body))` (small XML document; the flag is not passed) |

`UNSIGNED-PAYLOAD` leaves the body out of the signature: integrity in transit rests on TLS alone (no `Content-MD5` is sent on PUTs either). Acceptable because every connection is HTTPS and chunks are content-addressed and re-checked by the bucket function ([object-store-common §6](object-store-common.md)). Streaming (`aws-chunked`) signing exists in the library but is not used: every body is sent whole.

## 4. Operation mapping

All verbs run under the shared retry ladder ([06 §4.1](../06-backends.md)) with this store's `Health.t`, name `"s3"`. Inside an attempt, a library error classified Transient (§5) is raised so the ladder retries it; any other outcome, `Not_found` included, is returned to the verb, which interprets it after the ladder. The contract's `Stored_key` is rendered to its string before reaching these verbs.

| Contract op | HTTP | Success | Absent | Notes |
|---|---|---|---|---|
| `put k data` | `PUT /<b>/<k>`, body = data, `Content-Length` | any 2xx (reply must carry `ETag`, else a library failure → Transient) | — | Single request, never multipart (§4.1). No `Content-Type` (service default `binary/octet-stream`/`application/octet-stream`). |
| `put_if_absent k data` | as `put` plus `If-None-Match: *` | 2xx → return `data` (the same buffer) | — | 412 → `get k` and return the holder's body. Any other error → raised with its class (§4.2). |
| `get k` | `GET /<b>/<k>` | 2xx → whole body | 404 → Permanent failure `s3 get: not found` | Body read to the end (Content-Length or chunked framing) into one buffer. |
| `get_opt k` | `GET /<b>/<k>` | `Some body` | 404 → `None` | 403 is **not** absent (§8.3). |
| `get_range k off len` | `GET` + `Range: bytes=<off>-<off+len-1>` | 206 → body, then checked: longer than `len` → `Backend_error "s3 get_range <k>: asked for <len> bytes, got <n>"` | 404 → `None` | `len = 0` is not expressible (the contract forbids it). Short at EOF: S3 clamps the last index, so a range reaching past the end returns the tail. **Offset ≥ size → 416 `InvalidRange` → Permanent failure**, not the contract's empty answer (§10.4). |
| `head_opt k` | `HEAD /<b>/<k>` | entry: `size = Content-Length`, `last_modified = Last-Modified` (RFC 1123, whole seconds), `etag = ETag` unquoted | 404 → `None` | A 2xx missing any of the three headers → Permanent `unknown(1): Result did not return correct headers`. |
| `delete k` | `HEAD` (as `head_opt`), then `DELETE /<b>/<k>` | returns `head ≠ None` | DELETE's 2xx and 404 both succeed | S3 answers 204 whether or not the key existed, so existence is learnt from the HEAD (two requests per delete; racy by design — a concurrent writer between HEAD and DELETE makes the answer stale, acceptable for folder-marker moves). |
| `delete_multi ks` | `POST /<b>?delete` batches (§4.3) | — | absent keys succeed | Sequential batches of ≤ 1000. |
| `copy src dst` | `get src` then `put dst` | — | missing source → Permanent (`get`) | Not server-side `CopyObject`: the body crosses the client link twice ([06 §9.5](../06-backends.md)). Both halves run through the driver's own verbs, so neither is counted nor gated by the traffic wrapper. |
| `list_prefix ?max_keys p` | `GET /<b>?list-type=2&prefix=<p>[&max-keys=n][&continuation-token=t]` | concatenated `Contents` (§4.4) | empty list | Flat (no `delimiter`). |

### 4.1 No multipart

Every object is one `PUT` of the whole body. Reasons:
- Bodies are bounded: chunks are at most the domain's `chunkSize` (default 8 MiB), manifests and job objects are small. S3's single-PUT limit is 5 GiB.
- Multipart costs ≥ 3 requests (initiate, parts, complete), leaves billed orphans when a client dies mid-upload (the terraform lifecycle rule aborting incomplete uploads after 1 day exists for this and for the share function's multipart copies), has a 5 MiB minimum part size, and a multipart ETag is not an MD5.
- A single PUT is atomic: readers see the old object or the whole new one, never a partial — which is the contract's "must not expose a partial object".
- `If-None-Match` on a single PUT is the claim primitive; on multipart it applies at `CompleteMultipartUpload`, a second shape to get right.

The body buffer is read in place for the life of the request (64 KiB slices, one slice ahead of the socket), so it must stay valid and unmodified until the answer — retries resend the same buffer.

### 4.2 `put_if_absent` via `If-None-Match: *`

AWS S3 evaluates `If-None-Match: *` atomically: the first PUT to a free key succeeds, every later or concurrent one gets **412 `PreconditionFailed`** and the object is not replaced. The driver then reads the key back (`get`, with its own ladder) and returns that body: "the other writer's body". Emulating with HEAD+PUT would lose races silently and is never done.

Consequences and provider behaviour:
- A PUT that succeeded server-side but whose reply was lost (connection reset → Transient → retried) is answered 412 on the retry and returns the stored body, byte-identical to `data` but a different buffer. The caller (folder claim) compares by content (the marker's folder id), so it still reads as a win; the traffic wrapper counts the read-back as download.
- **409 `ConditionalRequestConflict`**: AWS returns it when a conflicting write to the same key is in flight and documents it as retryable. The driver maps it to Permanent (it is a non-412 4xx); the claim caller then treats the store as "cannot arbitrate" and falls back to a plain PUT (§10.2).
- **Providers that reject the header** (e.g. `501 NotImplemented`, or a 400): Permanent failure → the folder-claim caller logs once `"<domain>: this store cannot claim a name (…); folder ids are minted locally and concurrent creation of one directory can strand files"` and writes the marker with a plain PUT. Degraded but visible.
- **Providers that ignore the header** and overwrite: undetectable by the driver — every claimant is told it won. Only the conformance suite's racing-claims test (5 concurrent claims → one stored body, every claimant told that body) proves support, and it is configured for AWS only (no `endpoint` field; §8.4). Before relying on a provider, that test must pass against it.
- MinIO, Cloudflare R2 and Backblaze B2 have added conditional-write support at different times; support must be verified per deployment, not assumed from this list.

### 4.3 Bulk delete (`DeleteObjects`)

Per batch of ≤ 1000 keys (the service cap), in list order, sequentially:

```
POST /<bucket>?delete           (canonical query "delete=", wire "?delete=")
Content-MD5: base64(md5(body))  (required by S3; absent → 400)
Content-Length: …
<Delete><Quiet>false</Quiet><Object><Key>k1</Key></Object>…</Delete>
```
Keys are XML-escaped (`&`, `<`, `>`, quotes) by the XML writer; no `VersionId`. Non-quiet mode, so the response lists `<Deleted>` and `<Error>` elements; each `<Error>` carries `Key`, `Code`, `Message` (and optional `VersionId`).

- Request-level failure (non-2xx) → §5 mapping, ladder retries Transient.
- 2xx: every `<Error>` whose `Code` is not `NoSuchKey`/`NotFound` (`absent_code`) counts as refused. Any refused → raise `Retry.Failed{kind = Transient; op = "delete_multi"; detail = "<r> of <n> object(s) not deleted; first was <key>: <code> (<message>)"}`. Raised **after** the ladder, so it is not retried here; the caller (GC) decides. Transient rather than per-code because the codes are per key, a repeat is idempotent, and wrongly calling it permanent strands objects on a copy nothing walks again. Batches already sent stay deleted.
- Empty key list → no request.

### 4.4 Listing and pagination (`ListObjectsV2`)

- First page: `GET /<b>?list-type=2&prefix=<p>` plus `max-keys=<n>` iff `max_keys = Some n` with `n ≤ 1000` (a larger `n` is omitted; the service default is 1000 per page).
- Next pages: the same plus `continuation-token=<NextContinuationToken>` (and the same `max-keys`). Pagination continues while the response carries `NextContinuationToken` (`IsTruncated` is not consulted) and, when `max_keys` is set, until at least `max_keys` entries have been collected. The result is **not truncated** to `max_keys` (it can exceed it by up to one page); `max_keys` is a stop signal, which is what the contract asks (a bounded existence check costs one request).
- Each page is its own ladder run (`op = "ls"` for the first, `"ls-cont"` for the rest); a Permanent error on any page fails the listing (no partial result).
- Entry per `<Contents>`: `key = Key` (as listed), `size = Size`, `last_modified = LastModified` (ISO 8601 parsed to epoch seconds, fraction kept), `etag = ETag` unquoted. Keys come back in UTF-8 byte order. A directory marker (`…/`, zero bytes) is an ordinary entry. Pages are accumulated in reverse and concatenated once (linear in the number of entries).
- No `encoding-type=url` is requested; keys with XML-hostile bytes rely on the service's XML escaping.

## 5. Error mapping

The client library turns a response into one of six outcomes; the driver classifies them:

| HTTP / event | Library outcome | Contract class |
|---|---|---|
| 2xx | `Ok` | success |
| 404 | `Not_found` | `None` for `get_opt`/`get_range`/`head_opt`; success for `delete`; Permanent `not found` for `get` |
| 403 (any code: `AccessDenied`, `SignatureDoesNotMatch`, `RequestTimeTooSkewed`, `InvalidAccessKeyId`, `InvalidObjectState` for archived objects…) | `Forbidden` | Permanent |
| 3xx; or 4xx with code `PermanentRedirect`/`TemporaryRedirect` (with `Endpoint`) or `AuthorizationHeaderMalformed` (with `Region`) | `Redirect endpoint` | Permanent (redirects are not followed; the configured region/endpoint is wrong) |
| other 4xx with a parseable XML `<Error>` (412 `PreconditionFailed`, 409, 416 `InvalidRange`, 400, **429**…) | `Unknown(status, Code)` | Permanent, except 412 in `put_if_absent` (§4.2) |
| 500, 503 (`InternalError`, `SlowDown`, `ServiceUnavailable`) | `Throttled` | **Transient** |
| other 5xx (502, 504…) with a parseable XML `<Error>` | `Unknown(status, Code)` | Permanent |
| a response whose error body is not parseable XML (proxy HTML page, empty body on a 4xx/5xx), a malformed status line, DNS failure, connect/TLS failure, connection reset | exception | **Transient** (unrecognised exceptions are Transient by the shared rule) |
| connection-level failure reported by the library | `Failed exn` | Transient |

The rendered detail is `redirect`, `throttled`, `unknown(<status>): <Code>`, `forbidden`, `not found`, or the exception text; permanent failures are also logged at error level (`s3 <op> <key>: …`). This diverges from the shared HTTP rule (`5xx and 429 Transient, other 4xx Permanent`, [06 §3.1](../06-backends.md)) for 429 and for XML-bodied 502/504 (§10.3). Backblaze B2 answers overload with 503, which lands in `Throttled` and is retried.

## 6. Connections, TLS, timeouts

### 6.1 Pooling (in the client library, not the shared HTTP client)

- One process-wide pool keyed by `https:<host>:443`; unbounded concurrent connections (the caller's own concurrency bounds them); up to **32 idle** connections kept per key, extra ones closed.
- An idle connection older than **20 s** (`AWS_S3_POOL_MAX_IDLE_S` environment variable overrides; B2 reaps idle keep-alives aggressively) or found closed is discarded when taken.
- Returned to the pool only when the response was framed (Content-Length, chunked, or HEAD) and did not say `Connection: close`; otherwise closed (unconsumed bytes would corrupt the next request).
- A failure on a **reused** connection is retried once on a fresh connection **only for bodiless requests** (GET, HEAD, DELETE, list); PUT and the bulk-delete POST rely on the ladder, which rebuilds the body.
- A failed write closes the connection's read side so a pending response read errors instead of waiting forever.

### 6.2 TLS backend (process-global)

HTTPS goes through conduit, which has two TLS stacks compiled in or not by opam packages: `native` (ocaml-tls, package `tsync-tls`) and `openssl` (lwt_ssl + system libssl, package `tsync-ssl`). A build has at least one. Selection, highest priority first: `tsync start --tls native|openssl` (aliases `tls`, `ssl`); top-level config field `"tls": "native"|"openssl"`; else the preferred available one, **OpenSSL first** (much faster). An unknown name raises; a known name not compiled in falls back to the preferred one with a warning. The choice is one global for every conduit connection in the process (gcs and http-proxy clients too).

**OpenSSL error-queue bug**: over the OpenSSL path, some S3-compatible endpoints — Backblaze B2 reproducibly — fail on the *second* connection with `SSL routines::shutdown while in init`. OpenSSL's error queue is per thread, not per connection; an error left by one connection's shutdown is reported by the next connection's handshake. Nothing detects this automatically: a B2 user on an OpenSSL build sets `"tls": "native"`. Symptom: every request after the first fails with that TLS error, classified Transient, so the store climbs the ladder and trips its health hold rather than failing permanently.

Certificate checking is conduit's default: native authenticates against the system trust store (`ca-certs`); OpenSSL uses conduit's default client verification (hostname and IP checked). tsync configures neither.

### 6.3 Timeouts — none in the driver

The driver passes no connect timeout and wraps no request in a stall detector (unlike gcs, which uses the shared client's stall timeout; see [object-store-common §4](object-store-common.md)). A request to a peer that vanished without FIN or RST waits until the kernel gives up (TCP keepalive/retransmission limits, often many minutes). What bounds such a request in practice: a caller's own deadline (the FUSE chunk-read deadline; write-guard probes bounded at 10 s), or cancellation when the member is found down by another request (`until_held`). Consequence: S3 requests never register as timeouts with `Health.timed_out`, which the uplink governor reads as a congestion signal (§10.5).

## 7. Capabilities, concurrency, memory

- Capabilities, `watch` (2 s sleep), `verify_all`, `discard`, `fast_read = false`, `local_path = None`, no `get_many`/`list_many`: all from the shell ([object-store-common §2](object-store-common.md)). `share_url = shareUrl` when set. `verified = true` is asserted, relying on the terraform deployment.
- No `max_concurrency` opinion: parallelism is the caller's (mirror/sync pools, `batched_get_many`'s 32 slots).
- Memory per request: a GET holds the whole object body in one off-heap buffer (a chunk, ≤ chunk size); a PUT holds nothing extra beyond one 64 KiB slice in flight; with signed payloads the SHA-256 pass reads the body once more. Listing holds every entry of the prefix.

## 8. Service consistency and quirks relied on

1. **Strong read-after-write and list-after-write** (AWS since Dec 2020): a key written is immediately readable and listed; a delete is immediately visible. The journal, the cursor and claim read-back depend on it. S3-compatible services generally match; eventually-consistent ones would break journal ordering assumptions.
2. **Single PUT is atomic** and last-writer-wins at the key.
3. **Missing key vs permission**: without `s3:ListBucket` on the bucket, S3 answers a GET/HEAD of a missing key with **403**, not 404; the driver would then report every miss as a Permanent `forbidden`. The terraform client policy grants `ListBucket`.
4. **Region must match**: a wrong AWS region yields a 301/400 redirect error → Permanent. A region newer than the library's list must be spelled via `endpoint = s3.<region>.amazonaws.com` + `region = <region>`.
5. **Archived chunks**: a chunk transitioned to `GLACIER`/`DEEP_ARCHIVE` by a lifecycle rule answers GET with 403 `InvalidObjectState` → Permanent. The default archive class is `GLACIER_IR` (instant retrieval), which reads normally.
6. **Backblaze B2**: 503 for back-pressure (Transient); aggressive idle keep-alive reaping (20 s pool age); the OpenSSL error-queue failure (§6.2); endpoint `s3.<region>.backblazeb2.com` with its own region name.
7. **Cloudflare R2**: region is conventionally `auto`; endpoint `<account>.r2.cloudflarestorage.com`.
8. **MinIO**: HTTPS on 443 only — a MinIO on another port or plain HTTP is unreachable (no port or scheme in `endpoint`).
9. **Bucket notifications, Lambda, IAM** exist on AWS only: on an S3-compatible provider the server-side function is not deployed, yet the shell still reports `verified = true` and answers `discard` with `Queued` (§10.8).

## 9. Test-pinned invariants

Language-neutral statements, with where they are held:
- Classification: a Transient failure (e.g. 503) is retried to exhaustion (8 attempts); a Permanent one (403) is attempted once and reported (`tests/backends/backend_failure`).
- Real AWS S3 in CI (`tests/conformance`, native TLS build, run prefix `tsync/ci-<run id>/` swept afterwards; exits 2 when no store ran):
  - put/get round trip; `get_opt` and `head_opt` of an absent key are `None`; `head_opt` size; copy duplicates the body; listing sees both objects; `max_keys = 1` answers ≤ 1 entry; a list longer than one page is answered whole.
  - An 8 MiB position-dependent body comes back byte-identical (compared by hash); its `head_opt` size is exact.
  - Ranges over an 8 MiB object: start, middle, ending on the last byte are the exact bytes; a range reaching past the end returns the tail only; a range of an absent key is `None`.
  - Five concurrent `put_if_absent` on one key leave one stored body and every claimant is answered with it; a later claim is refused and told the holder, holder untouched; an unclaimed name answers with the caller's own body (also with a chunk-sized holder).
  - `delete` answers true then false; `delete_multi` over > 1000 mostly-absent keys with survivors at the front, on the 1000 boundary and past it, removes every survivor.
  - Keys `amp-&-key`, `angle-<tag>-key`, quotes, `plus+key`, `percent-%2F-key`, `hash#and?query`, `space in key`, `unicode-é-å-日本` each round-trip through put/get and are removed by `delete_multi`.
  - `capabilities` answers with `verified = true`; `verify_all` queues 4096 objects naming shards; `discard` writes a request carrying exactly the keys; the deployed function removes a chunk named in a discard.
- Client library unit tests (fork): path encoding escapes `%` and `+`, keeps the unreserved set, pads low bytes, round-trips through a decoder; the wire request target equals the signed encoding; SigV4 presign vectors.

## 10. Open questions / inconsistencies

1. **`region` is required although documented and spec'd as defaulting to `us-east-1`**: the factory reads it with "missing field" failure; only the wizard fills the default. Likewise an explicit `"endpoint": ""` is passed through as a vendor host `""` (the gcs driver filters empty strings; s3 does not). Both should be normalised at registration.
2. **409 `ConditionalRequestConflict` is Permanent**, so a genuine claim race on AWS can push the loser into the "store cannot arbitrate" fallback, which plain-PUTs over the winner. It should be Transient (retry the conditional PUT).
3. **Error classes diverge from the shared HTTP rule**: 429 and XML-bodied 502/504 are Permanent here, Transient in `Http_client`. Whether an error body parses decides the class of a 5xx.
4. **`get_range` with offset ≥ size fails (416)** instead of answering 0 bytes as the contract says. No caller is known to ask for it; the local driver does return empty.
5. **No request timeout or stall detection** (§6.3): a silently dead connection holds a request, a batch-read slot and possibly an uplink admission indefinitely, and S3 never feeds the governor's timeout signal. Moving S3 onto the shared stall-timeout client (or wrapping each attempt in `with_stall_timeout`) would align it with gcs.
6. **No detection of providers that ignore `If-None-Match`** and no way to run the conformance suite against a custom endpoint (its s3 candidate reads no endpoint variable).
7. **`delete` costs HEAD + DELETE** ([06 §9.6](../06-backends.md)); `copy` is get+put and bypasses the traffic counter and the uplink gate.
8. **`verified = true` / `discard = Queued` on providers with no function** (§8.9): an S3-compatible bucket without the AWS deployment claims checks nobody runs and accepts delete requests nobody consumes (the named chunks stay on that store; only `tsync gc --status` shows the requests piling up).
9. **IPv4-only, port 443 only, path-style only**: fixed in the endpoint construction, not configurable.
10. **Static credentials only**: no STS session token, no instance role, no credential file.
