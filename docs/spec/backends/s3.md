# Backend driver: `s3` (AWS S3 and S3-compatible services)

How the `s3` driver realises [the store contract](../06-backends.md). What every bucket answers the same way (capabilities, watch, verification, discard, the transport, the bucket-side function) is in [object-store-common.md](object-store-common.md). This file covers what is S3-specific: configuration, addressing, signing, the verbs' requests, and the service's quirks.

Implementation notes: [../ocaml/backends/s3.md](../ocaml/backends/s3.md).

---

## 1. Configuration

The backend object's generic fields (`type`, `name`, `role`, `link`) are in [05-ops-config.md](../05-ops-config.md). Driver fields:

| Field | Type | Default | Meaning / validation |
|---|---|---|---|
| `bucket` | string | required | Bucket name, the first path segment. It MUST be non-empty and MUST NOT contain `/`; it is percent-encoded like a key segment. |
| `region` | string | `us-east-1` | SigV4 signing region. Absent and `""` both mean the default. Any name matching `[a-z0-9-]+` is accepted. |
| `endpoint` | string | `""` = AWS | An S3-compatible service: a bare host (`minio.lan`), `host:port`, or `https://host[:port]`. `http://` is accepted only for a loopback host. No path. `""` and absent both mean AWS. |
| `accessKeyId` | string | required | SigV4 access key. |
| `secretAccessKey` | string, secret | required | SigV4 secret. Masked in every rendered configuration. |
| `unsignedPayload` | bool | `false` | Sign object uploads with `UNSIGNED-PAYLOAD` instead of the body's SHA-256 (§3.2). JSON booleans and the strings `true/1/yes/on`, `false/0/no/off` (any case) are accepted; any other value MUST be refused. |
| `shareUrl` | string | `""` = none | Base URL of the share endpoint deployed beside the bucket. `""` and absent both mean none. |
| `etagIsMd5` | bool | `true` | The ETag of an object this driver wrote is the MD5 of its body, and is reported as its checksum (§4.5). `false` for a bucket encrypting with SSE-KMS or SSE-C, or a provider whose ETag is not the MD5. Spellings as `unsignedPayload`. |

Endpoint resolution:

- Without `endpoint`, the host is `s3.<region>.amazonaws.com`, or `s3.<region>.amazonaws.com.cn` for a region starting `cn-`, on port 443.
- With `endpoint`, the host and port are the endpoint's, and the region is only signed, never interpreted.

Credentials are static keys only. Building a store reaches no network.

## 2. Addressing and request shape

- **Path-style** always: `https://<host>/<bucket>/<key>` for object operations, and `https://<host>/<bucket>?…` for bucket operations. AWS, R2, B2 and MinIO accept it.
- **Key encoding.** Every byte outside `[A-Za-z0-9_.~-]` and `/` is percent-encoded as `%XX` with uppercase hex, including `%` and `+`. The **same** encoded string is used as the canonical URI in the signature and as the request target on the wire. A mismatch between the two answers 403 `SignatureDoesNotMatch` on every key that holds such a byte.
- **Query encoding.** Each `k=v` pair percent-encodes everything outside the unreserved set (`/` becomes `%2F`). The canonical query is the pairs sorted as strings and joined with `&`.
- HTTP/1.1 with persistent connections ([01 §10](../01-core.md#10-http-request-discipline)).

## 3. Authentication: SigV4

### 3.1 Signing

Header-based AWS Signature Version 4, service `s3`, per attempt:

1. `canonical_request = VERB \n canonical_uri \n canonical_query \n canonical_headers \n signed_headers \n payload_hash`. Every header sent is signed: lower-cased names, sorted, `name:value\n`.
2. `scope = <YYYYMMDD>/<region>/s3/aws4_request`; `string_to_sign = "AWS4-HMAC-SHA256\n<YYYYMMDDTHHMMSSZ>\n<scope>\n" ^ hex(sha256(canonical_request))`.
3. `signing_key = HMAC(HMAC(HMAC(HMAC("AWS4"^secret, date), region), "s3"), "aws4_request")`, cached per (access key, region, date).
4. `Authorization: AWS4-HMAC-SHA256 Credential=<akid>/<scope>,SignedHeaders=<…>,Signature=<hex>`.

**Clock skew.** The date is the local wall clock when the attempt is built, so a retry is never stale by the ladder's own delays. S3 refuses a request more than 15 minutes off with 403 `RequestTimeTooSkewed`: REFUSED, with the reason "local clock is off by more than 15 minutes".

### 3.2 Payload hash

| Request | `x-amz-content-sha256` |
|---|---|
| GET, HEAD, DELETE, list | `hex(sha256(""))` |
| Object PUT, `unsignedPayload = false` | `hex(sha256(body))`, computed per attempt |
| Object PUT, `unsignedPayload = true` | `UNSIGNED-PAYLOAD` |
| Bulk-delete POST | `hex(sha256(body))` always |

`UNSIGNED-PAYLOAD` leaves the body out of the signature, so integrity in transit rests on TLS alone. That is acceptable because every non-loopback connection is verified HTTPS, and chunks are content-addressed and checked by the bucket function.

## 4. Operations

| Contract op | Request | Success | Notes |
|---|---|---|---|
| `put` | `PUT /<b>/<k>`, `Content-Length` | 2xx | One request, never multipart (§4.1). |
| `put_if_absent` | as `put`, plus `If-None-Match: *` | 2xx → `Won` | 412 `PreconditionFailed` → `get` the holder (§4.2). 409 `ConditionalRequestConflict` → TRANSIENT/LOAD, retried with the header intact. 501 `NotImplemented`, or 400 naming the header → REFUSED ("this store cannot claim a name"). |
| `put_if_unchanged` | as `put`, plus `If-Match: "<expected.etag>"`, or `If-None-Match: *` for `none` | 2xx → `Written` | 412 `PreconditionFailed`, or 404 `NoSuchKey` under `If-Match` → `Changed`. 409 `ConditionalRequestConflict` → TRANSIENT/LOAD, retried with the header intact. 501 `NotImplemented`, or 400 naming the header → REFUSED ("this store cannot replace conditionally"). |
| `get` / `get_opt` | `GET /<b>/<k>` | 2xx → body | 404 → ABSENT / `none`. |
| `get_range` | `GET` + `Range: bytes=<off>-<off+len−1>` | 206 → body, checked against `Content-Range` | 404 → `none`; 416 `InvalidRange` → empty body; a 200 with the whole object where more than `len` bytes remain → CORRUPT. |
| `head_opt` | `HEAD /<b>/<k>` | entry: `Content-Length`, `Last-Modified`, `ETag` unquoted, checksum per §4.5 | 404 → `none`. A 2xx missing one of the three headers → CORRUPT. |
| `delete` | `HEAD`, then `DELETE /<b>/<k>` only if the HEAD found the object | `true` after a 2xx DELETE | HEAD 404 → `false`, with no DELETE. S3's DELETE answers 204 whether or not the object existed. |
| `delete_multi` | `POST /<b>?delete` pages (§4.3) | | |
| `copy` | server-side `PUT /<b>/<dst>` with `x-amz-copy-source: /<b>/<src>`, or `get` + `put` | | A server-side copy's 200 whose body is an `<Error>` is a failure mapped by its code. A missing source → ABSENT. |
| `list_prefix` | `GET /<b>?list-type=2&prefix=<p>[&max-keys=n][&continuation-token=t]` | concatenated `<Contents>` (§4.4) | |
| `compute_checksum(k, md5)` | `head_opt` | the entry's checksum | an entry without one → `get`, and hash the body |

### 4.1 One request per object

- Chunks are bounded by the domain's chunk size, and every other object is small. S3's single-request limit is 5 GiB.
- A single PUT is atomic, so readers see the old object or the whole new one.
- `If-None-Match` on a single PUT is the claim primitive.
- Multipart would cost at least three requests, leave billed orphans when a client dies mid-upload, and move the precondition to the completion request.

### 4.2 Claims

- AWS S3 evaluates `If-None-Match: *` atomically: the first PUT to a free key succeeds, and every later or concurrent one gets 412 without replacing the object.
- The driver then reads the key back and answers `Held` with its body, or `Won` if the body is byte-identical to its own. That also covers a PUT that succeeded but whose answer was lost: the retry is answered 412, and the stored body is its own.
- **Providers that ignore the header** and overwrite are undetectable from one claim. Before a store with a custom `endpoint` is trusted to arbitrate, the driver SHOULD confirm support once per process: re-claim an existing immutable object with its own bytes. The empty chunk serves in every domain: it is written plainly first, so the check works before the domain holds anything. A provider that honours the precondition answers 412. A provider that answers 2xx rewrote identical bytes, which is harmless, and has shown that it ignores the precondition: every later claim on that store fails REFUSED. `rclone serve s3` is such a provider.
- **A range answered 200 with a `Content-Range`** (rclone) is a range answer, checked as a 206.
- **Conditional replace** is confirmed the same way, once per process, on a store with a custom `endpoint`: put the empty chunk with its own bytes under `If-Match` naming an ETag it cannot have (32 zeros). A provider that honours the precondition answers 412. One that answers 2xx rewrote identical bytes, harmlessly, and has shown that it ignores `If-Match`: every later `put_if_unchanged` on that store fails REFUSED without sending. A store whose claims were found ignored is not trusted with a conditional replace either.

### 4.3 Bulk delete

Per page of at most 1000 keys, in order, sequentially:

```
POST /<bucket>?delete
Content-MD5: base64(md5(body))
<Delete><Quiet>true</Quiet><Object><Key>k1</Key></Object>…</Delete>
```

- Keys are XML-escaped (`&`, `<`, `>`, `"`, `'`). A key holding a character XML 1.0 cannot carry is deleted with a single DELETE instead.
- A request-level failure is mapped per [failure-model §4.2](../algorithms/failure-model.md#42-http-object-stores), and the ladder retries TRANSIENT kinds.
- A 2xx answer lists only refusals (quiet mode). Each `<Error>` is mapped by its `Code` per [failure-model §4.2](../algorithms/failure-model.md#42-http-object-stores).
- An empty key list issues no request.

### 4.4 Listing

- `max-keys` is sent as `min(n, 1000)` when `max_keys = n`.
- Next pages add `continuation-token=<NextContinuationToken>`. Paging continues while the answer carries a token, and stops early once `max_keys` entries are held.
- Each page is one run of the retry ladder, and a failure on any page fails the listing.
- Entry per `<Contents>`: `Key`, `Size`, `LastModified` (ISO 8601, fraction kept), `ETag` unquoted, checksum per §4.5.
- The shell sorts, truncates and omits invalid names ([object-store-common §2.1](object-store-common.md#21-verbs-a-driver-supplies)).

### 4.5 Checksums

- With `etagIsMd5`, an ETag of exactly 32 hex characters is reported as the checksum `md5:<lowercase ETag>`. Any other ETag (a multipart `…-<n>`) carries none.
- S3 sets the ETag of an object uploaded in one request, stored unencrypted or with SSE-S3, to the MD5 of its body, and this driver writes every object in one request (§4.1). The ETag comes in every listing, so a comparison costs no request per object.
- The additional checksums S3 can keep (`x-amz-checksum-*`) are not used: listings do not carry their values, and reading one costs a HEAD per object.
- Without `etagIsMd5` the store reports no checksum, and `compute_checksum` downloads the body.
- A wrong `etagIsMd5: true` (a KMS-encrypted bucket, a provider with other ETags) yields values that never equal a real MD5: comparisons find a difference and copy, never a false equality.

## 5. Error mapping

Kinds are [failure-model §4.2](../algorithms/failure-model.md#42-http-object-stores). How S3's answers meet its rows:

- **Throttling** (TRANSIENT/LOAD): 503 `SlowDown` or `ServiceUnavailable`, 429, and 409 `ConditionalRequestConflict`.
- **Other 5xx**, including 500 `InternalError`: TRANSIENT/LINK.
- **403** (`AccessDenied`, `SignatureDoesNotMatch`, `InvalidAccessKeyId`, `RequestTimeTooSkewed`, `InvalidObjectState` for an archived object): REFUSED, with the code as the reason.
- **Redirects** (a 301, or a 4xx `PermanentRedirect`, `TemporaryRedirect`, `AuthorizationHeaderMalformed`): REFUSED, "the bucket is in another region or endpoint", naming it when the answer does.

Without `s3:ListBucket`, S3 answers a read of a missing key with 403, not 404, so every miss would be REFUSED. The client's grant MUST include listing the bucket.

## 6. Transport

- The shared transport of [object-store-common §4](object-store-common.md#4-transport) and [01 §10](../01-core.md#10-http-request-discipline): pooled connections, verified TLS, the stall detector, and admission per attempt ([06 §6](../06-backends.md#6-the-admission-seam)).
- A failure on a reused connection before any byte of the answer arrived is retried once on a fresh connection, for every verb. The body is re-sent from the caller's buffer.
- A TLS library whose error state is shared across connections MUST have it cleared around every handshake and shutdown. Otherwise an error left by one connection's shutdown fails the next connection's handshake: Backblaze B2 over OpenSSL fails every request after the first that way.

## 7. Service consistency and quirks relied on

1. **Strong read-after-write and list-after-write.** A write is immediately readable and listed, and a delete immediately visible. An S3-compatible service without them MUST NOT be configured.
2. **A single PUT is atomic**, last writer wins.
3. **Region must match.** A wrong AWS region is REFUSED with the redirect's hint.
4. **Conditional writes** (`If-None-Match: *`, `If-Match`) on a single PUT are evaluated atomically by AWS S3. S3-compatible providers vary.
5. **Archived chunks.** A chunk transitioned to an offline class answers 403 `InvalidObjectState`: REFUSED. Only online archival classes are allowed ([object-store-common §5.5](object-store-common.md#55-deployment-requirements)).
6. **Backblaze B2:** 503 for back-pressure (LOAD); idle keep-alive connections reaped within seconds; its own region names.
7. **Cloudflare R2:** region `auto`.
8. **The bucket-side function** exists only where it was deployed. On an S3-compatible provider it usually is not, and the store then answers as unconfirmed ([object-store-common §3](object-store-common.md#3-confirming-the-bucket-side-function)).

## 8. Conformance

Beyond [06 §10](../06-backends.md#10-conformance) and [object-store-common §8](object-store-common.md#8-conformance), run against real AWS S3 and against every S3-compatible endpoint that is to be supported:

- The generic store conformance, including racing claims and keys holding `& < > " ' + % # ? space` and non-ASCII characters.
- 503 is retried to the ladder's limit; 429 and 409 `ConditionalRequestConflict` are LOAD; 403 is attempted once.
- A range starting at or past the end answers an empty body.
- `region` absent uses `us-east-1`; `endpoint: ""` means AWS; an unlisted region name builds a store.
- Path encoding escapes `%` and `+` identically in the signature and on the wire; SigV4 test vectors pass.
- The ignoring-provider checks refuse claims on a store that overwrites under `If-None-Match`, and conditional replaces on a store that overwrites under either `If-None-Match` or `If-Match`.
- `put_if_unchanged` with the ETag just read answers `Written`; with a stale ETag, `Changed`; under `If-Match` on an absent key, `Changed`.
- With `etagIsMd5`, an entry of an object written by the driver carries `md5:<hex>` equal to the MD5 of the body read back, in a listing and on HEAD; a multipart ETag carries none; with `etagIsMd5: false`, no entry carries one.
- A silent connection is cut by the stall detector and counted as a timeout.
