# Backend driver `s3` (and the object-store common shell) — OCaml implementation notes

Companion to the language-neutral specs [../../backends/s3.md](../../backends/s3.md) and [../../backends/object-store-common.md](../../backends/object-store-common.md). General backend notes: [../06-backends.md](../06-backends.md).

## Where the current code differs from the spec

S3 driver:

- **`region` is required at runtime** (the factory fails "missing field") although it defaults to `us-east-1` in the documentation; the wizard fills it. `endpoint: ""` reaches `Region.vendor` as a host `""`.
- **Regions** outside the library's hard-coded list of 18 raise `Failure "Unknown region"` at store construction; newer regions need `endpoint = s3.<region>.amazonaws.com`.
- **Endpoint** is a bare host only; the port is always 443 and the scheme always https. The host is resolved `AF_INET` only, first address.
- **No timeout of any kind**: no connect timeout and no stall detector, so a silent connection holds a request, a batch slot and an uplink admission until the kernel gives up, and S3 never feeds the governor's timeout signal.
- **Error classes**: only `Throttled` (500, 503) and `Failed _` are Transient. 429 and XML-bodied 502/504 are Permanent (`Unknown`), while an error body that does not parse as XML raises inside the library and reaches the ladder as an unrecognised exception → Transient, so the class of a 5xx depends on its body.
- **409 `ConditionalRequestConflict`** is Permanent; the folder-claim caller then logs "this store cannot claim a name" and writes the marker with a plain PUT, possibly over the real winner.
- **`get_range` with offset ≥ size** fails 416 → Permanent.
- **`copy`** is `get` + `put` through the driver's own verbs, neither counted nor gated.
- **`delete`** is HEAD then DELETE, and issues the DELETE even when the HEAD found nothing.
- **Listing** is not truncated to `max_keys` (it can exceed it by up to one page).
- **A retry on a reused connection** happens once, for bodiless requests only.
- **`unsignedPayload`**: an unparseable value reads as `false`.
- **OpenSSL error-queue bug**: over the OpenSSL path, Backblaze B2 fails the second connection with `SSL routines::shutdown while in init` (the per-thread error queue carries one connection's shutdown error into the next handshake). Nothing clears it; the workaround is `"tls": "native"`.

Object-store shell:

- **`verified = true` and `discard = Queued` are literals**: a bucket without the function (manual setup, S3-compatible provider, `manage_notifications = false` never wired) claims checks nobody runs and accepts deletes nobody executes. There is no probe.
- **Job PUTs** (`verify_all`, `discard`) go through the driver's `put` directly, beneath the traffic wrapper: neither counted nor gated.
- **`verify_all`** starts all 4096 PUTs as pending promises and bounds only those in flight (32).
- **s3 does not use the shared `Http_client`**, so pool limits, the stall timeout and status classification differ between the two object stores.

## Bucket-side function and deployment (Python, terraform)

- One module, `lambda/verify.py`, with two entry points (`handler` for AWS, `gcp_verify` for GCP) and one storage adapter per cloud (`STORE=aws|gcs`, default `aws`, `lambda/store_aws.py` over boto3, `lambda/store_gcs.py` over google-cloud-storage), built lazily so importing needs no credentials.
- Adapter surface: `get_bytes` (missing → `FileNotFoundError`), `put_bytes`, `delete` (absent not an error), `delete_many → [(key, code)] refused`, `list_keys`, `read_chunk` (AWS streams 1 MiB slices; GCS downloads whole).
- AWS `delete_many`: `DeleteObjects` in batches of 1000, `Quiet=true`. GCS: the JSON batch endpoint, 100 sub-requests per call; a failed batch is redone key by key with 32 threads.
- AWS events: `Records[].s3.object.key`, URL-encoded with `+` for space → `unquote_plus`; each record in its own `try`, and no exception escapes (S3 would redeliver the whole notification). GCP: CloudEvent `.data.message` or the legacy background dict, key = `attributes.objectId`; exceptions propagate, the trigger has `DO_NOT_RETRY`.
- The function mirrors OCaml constants by comment, not generation: `ROOT`, `FANOUT = 3`, `KEY_HEX = 16`, `%016x`, the marker JSON fields. `tests/unit/hash` golden vectors are the only mechanical cross-check.
- Terraform modules `store-s3` and `store-gcs` provision the bucket (or adopt one with `create_bucket = false`), client credentials, the verify function and trigger, optionally the share function (`deploy_share`), and lifecycle rules (`manage_lifecycle`, `archive_domains`, `extra_lifecycle_rules`). Lambda `python3.13` on arm64 (the vendored `xxhash` wheel is aarch64; `vendor/` is appended to `sys.path`); Cloud Functions gen2 `python313`. Defaults: `verify_timeout_seconds = 120`, `verify_memory_mb = 512`, `verify_max_concurrency = 32` (`reserved_concurrent_executions` / `max_instance_count`). On AWS the `aws_s3_bucket_notification` resource owns the bucket's whole notification configuration (`manage_notifications = false` leaves wiring to the operator). The GCS verify reader is bucket-wide (`objectViewer`), wider than the AWS policy, flagged in the module for narrowing.
- `terraform/ci/` deploys only the verify half over existing CI buckets; `tests/conformance` then checks `verify_all`, `discard`, and that the live function removes a discarded chunk.

## S3 driver

### Runtime-independent

- **The client library is a pinned fork**: `opam pin add git+https://github.com/toots/aws-s3.git#tsync` (`scripts/opam_deps.sh`). Upstream `aws-s3` lacks what the driver depends on: `?precondition:[`If_none_match | `If_match of etag]` on `put` (upstream only had `meta_headers`, which become `x-amz-meta-*` and could not carry `If-None-Match`); `put_bigstring`/`get_bigstring` and `Body.Bigstring`; `?unsigned_payload`; path encoding that escapes `%` and `+` identically in the signed canonical URI and on the wire (both were 403s); the keep-alive connection pool with idle-age reaping; the write-failure path that closes the read side. A reimplementation over another S3 library must re-check each of these.
- **`(optional)` library + `select` = silent absence**: `tsync_s3_backend` is `(optional)` and `lib/backends/dune` selects `s3_link.enabled.ml` / `s3_link.disabled.ml` on it. A broken dependency list once made dune skip the library without error for several commits (the stanza's dependencies had been joined into one name); every build stayed green with s3 uncompiled. The conformance suite now builds through the registry and exits 2 when no store ran; checking `Backend_lwt.types ()` contains `"s3"` is the cheap guard.
- **Registration keeps field parsing out of the driver**: the factory (`s3_backend_lwt.ml`) reads string fields; `unsignedPayload` is passed as `None` unless true so an unset field leaves the library's default alone. `endpoint` is passed raw (`Some ""` reaches `Region.vendor`), unlike gcs's `opt` helper (see "Where the current code differs" above).
- **`Aws_s3.Region.of_string` raises `Failure`** for any region name outside its hard-coded variant list; it runs in `make_t`, so a newer AWS region fails at store construction, not at first request. `Region.vendor` bypasses the list.
- **Library error variant → contract class** is one function (`is_transient`: `Throttled | Failed _`). The library's `do_command` parses the XML error body of every non-404/403 4xx and of non-500/503 statuses with `Ezxmlm`; a body that does not parse raises an OCaml exception *inside* the deferred, which escapes the result type entirely and reaches the ladder as an unrecognised exception → Transient. The class of a 502 therefore depends on whether its body is XML.
- **412 is matched structurally** as `Error (S3.Unknown (412, _))`; 409 falls to the generic `Error e → raise (failed …)` and is Permanent.
- **`delete_multi` raises after the ladder**: the `Retry.failed ~kind:Transient` for per-key refusals is raised outside `with_retry`, so it is not retried by the driver; only a request-level transient is. Batching uses two `List.filteri` passes per batch (quadratic in the number of batches, fine at GC batch sizes).
- **`list_all` accumulates pages reversed** and concatenates once; the `enough` check recomputes `List.length (List.concat acc)` per page, which is quadratic only when `max_keys` is set (small by construction).
- **Bigstring ownership**: `put_bigstring` reads the caller's buffer in 64 KiB `Bigstringaf.substring` slices, one slice ahead of the socket (a `flush` bounds the pipe). The buffer must not be released or reused until the promise resolves; retries rebuild the reader over the same buffer. Unsigned=false hashes the whole bigstring (`Digestif.SHA256.digest_bigstring`) per attempt.
- **Physical identity of the claim answer**: `put_if_absent` returns `data` itself on success (`Io.return data`), which the traffic wrapper's `held != data` test depends on. A lost-reply retry answered 412 returns a fresh buffer with equal bytes.
- **Signing key cache** is a module-level `Hashtbl` in the library keyed by (access key, region), not thread-safe; fine under one Lwt thread.

### Lwt / functor-specific (and what each becomes under OCaml 5)

- **The driver is a functor over the library's own concurrency signature**: `Over (Io) (S3io : Aws_s3.Types.Io with type 'a Deferred.t = 'a Io.t) (Loop) (Bounded) (Clock)`, applied once as `Over (Io_lwt.Core) (Aws_s3_lwt.Io) (Retry_lwt) (Io_lwt.Bounded) (Io_lwt.Clock)`. The sharing constraint pins aws-s3's deferred to tsync's `Io.t` so no conversion is needed. Taking the *notion* (`Types.Io`) rather than the applied `Aws_s3_lwt.S3` keeps the driver free of Lwt. Under direct style this collapses: the library would need a direct-style `Io` (its `Pipe`, `Ivar`, `Deferred` become blocking/fiber primitives) — a larger port than tsync's own code.
- **The library's I/O is Lwt pipes with `Lwt.async` producers**: the connection reader, the writer loop and every body reader are `Lwt.async` fibers that die with their pipe. A body reader that raises only prints `Create_reader raised` to stderr. Exceptions inside `Lwt.async` in the library (a TLS shutdown on a peer-closed socket) were once leaking fds in CLOSE-WAIT; closes are now wrapped. Under effects these become fibers in a switch, which makes their lifetime explicit instead of tied to pipe closure.
- **No per-request timeout** means a promise can stay pending forever on a dead socket; cancellation from `Health_wait.until_held` or a caller's `Lwt.pick` deadline is what frees it. `Lwt.cancel` on a pending library call leaves its pooled connection in an unknown state; the pool only discards it on the next take if the pipe was closed. Under Eio, a cancelled fiber's switch would close the socket deterministically.
- **The connection pool is a module-level `Hashtbl` of `Queue`s** in the library, touched without locks: correct only because Lwt callbacks never interleave between a `Queue.take` and its use. With domains it needs a mutex.
- **The TLS backend is a global ref** (`Conduit_lwt_unix.tls_library`) set by `Tls_conf.apply` from the config (in `make_conf`) or `--tls`; it must be set before the first connection and affects every conduit user in the process. Which backends exist is decided when conduit is *built*, from its opam depopts (`tls-lwt` → native, `lwt_ssl` → OpenSSL): `tsync-tls` / `tsync-ssl` are virtual packages that pull them, and opam rebuilds conduit when one appears. Depending on `tls` instead of `tls-lwt` gives conduit no native backend at all — the stub that refuses every https connection; builds only worked while another package happened to pull `tls-lwt`. Under OCaml 5 with Eio the TLS choice moves to the flow constructor (`Tls_eio` vs an OpenSSL binding); the OpenSSL error-queue bug is a property of calling OpenSSL from one system thread for many connections without clearing `ERR_get_error`, and would recur in any binding that does not clear the queue per call.

## Object-store common

### Runtime-independent

- **The shell is a functor over the verbs** (`Object_store.Over (Io) (Bounded) (Clock) (V : VERBS)`) returning a first-class `(module Store)`. It replaced sixty identical lines at the end of each driver; adding a verb to the contract means adding it here once, not per driver.
- **`put_text` wraps job bodies with `Bigstring.of_string`**: job bodies are strings (empty verify jobs, newline-joined GC keys); only chunk bodies are kept off-heap.
- **`verified = true` and `Queued` are literals** in the shell. Nothing in the type system distinguishes "asserted" from "measured"; a probe would have to be added here, once, for both drivers.
- **Http_client is parameterised by a `POOL` module** (sockets) so `lib/core` links neither cohttp-lwt-unix nor a scheduler; `http_client_lwt.ml` binds it to `Cohttp_lwt_unix.Connection_cache` and maps its `Connection.Retry` to `Redial`. Bodies cross as `Bigstring.t`; the request body is `Cohttp_lwt.Body.of_bigstring (`Passthrough b)` (the cohttp fork `toots/ocaml-cohttp#bigstring-body`), so it is sent without a copy and must stay valid until the call resolves.
- **Headers are a thunk** (`unit -> Cohttp.Header.t io`) so gcs token minting runs inside the stall deadline.
- **The stall timeout is a global `ref`** (`Uplink_budget.stall_timeout`) read by gcs at construction: one number for the uplink window and the request deadline.
- **Pool replacement on `Redial` compares by physical identity** (`if t.cache == used then t.cache <- new_cache ()`) so concurrent requests that raced into the same dead pool share one redial.
- **The Python function mirrors OCaml constants by comment**, not by generation: `ROOT`, `FANOUT = 3`, `KEY_HEX = 16`, `%016x` formatting, the marker JSON fields. `tests/unit/hash` golden vectors are the only mechanical cross-check (chunk key); layout constants are checked by the Python tests' own expectations.

### Lwt / functor-specific (and what each becomes under OCaml 5)

- **`with_stall_timeout`** is `Lwt.pick [f alive; watch ()]` where `watch` sleeps until `last_heard + seconds` and re-arms; `alive` is a closure the body stream calls per piece (`Lwt_stream.map`). `Lwt.pick` cancels the losing side, which cancels the cohttp call mid-body. Under Eio: `Fiber.first` with the same re-arming sleep, or `Eio.Time.with_timeout` re-entered per piece.
- **`Verifier.queue` uses `Io.iter_p` over all 4096 shards with a `Bounded` pool of 32**: 4096 promises exist at once, 32 hold a slot. Under fibers the same shape spawns 4096 fibers; a worker-pull loop over a list (as the local walk does) bounds live tasks too.
- **Every verb is `Loop.with_retry … (fun () -> …)`** whose thunk re-runs the whole request, rebuilding the body reader; nothing in the retry holds a socket across attempts. This carries over unchanged to direct style.
