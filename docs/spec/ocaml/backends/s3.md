# Backend driver `s3` (and the object-store common shell) — OCaml implementation notes

Companion to the language-neutral specs [../../backends/s3.md](../../backends/s3.md) and [../../backends/object-store-common.md](../../backends/object-store-common.md). General backend notes: [../06-backends.md](../06-backends.md).

Code: `lib/store/s3/s3.ml` (the driver, with its own SigV4), `lib/store/object_store.ml` (the shell), `lib/store/bucket_xml.ml` (the bulk-delete XML, shared with gcs), `lib/store/bucket_function.ml`, `lib/http` (the transport).

## Object-store shell

### Map

| Spec (object-store-common) | Code |
|---|---|
| Verbs a driver supplies (§2.1) | `Object_store.verbs`: one attempt each, `delete_page` for at most `Object_store.page` (1000) keys, `list_page` returning `raw_entry` values and the next token |
| What the shell answers (§2.2) | `Object_store.make`: every verb inside `Retry.ladder ~health`, uploads inside `Uplink.admitted`, `Store.checked` around the whole record |
| Listing | `list_all`: pages until the token ends or `max_keys` entries are held, names through `Store.listed`, sorted by `Key.compare`, cut to `max_keys` |
| Bulk-delete paging | `chunks page keys`, one ladder per page, stopping at the first failed page |
| `compute_checksum` | `head_opt`, then `Checksum.of_body` over `get_opt` when the entry's checksum is of another algorithm |
| Status to kind (§4) | `Object_store.status_failure`, `Object_store.per_key_failure` |
| Confirming the function (§3) | `Bucket_function.open_`, `confirmed`, `due`, `probe`; driven by `Composite.probe`, read by `Composite.function_confirmed` |
| Transport (§4) | `Tsync_http.Client.endpoint`, `Client.request` (pool, one redial, stall timeout, `headers` computed per attempt); `Tsync_http.Transport` (TCP, OpenSSL or ocaml-tls) |
| Request objects | `Key.verify_job`, `Key.gc_jobs`, `Discards.request_key`, `Discards.body` |

### Departures

- **`capabilities` answers `verified = false`.** The confirmation is the owner's local state, so `Composite` adds it (`confirmed`); see [../06-backends.md](../06-backends.md).

### Learnings

- **`watch` sleeps through `Stop.sleep`**, so a stopping process leaves it at once.
- **The shell owns the ladder, the admission and the counters; a verb is one attempt.** A driver cannot forget to admit a retry or to count a body, and adding a contract operation is one edit here.
- **The body of a claim that lost is counted as a download** (`Held b` in `put_if_absent`), as 06 §6 asks.
- **`status_failure` classifies by status and by two substrings of the body** (`SlowDown`, `onflict`); a 4xx whose service code says "again" is the driver's to correct. S3's `fail` turns `RequestTimeout` into LINK and `OperationAborted` into LOAD (pitfall B-2.11).
- **`get_range` is checked twice.** The driver checks `Content-Range` against the offset; the shell fails CORRUPT on any answer longer than asked, whatever the driver did.
- **The stall timeout is the client's default (60 s), equal to `Uplink`'s `stall_timeout`**: the two constants are separate definitions (`default_stall` in `client.ml`, `stall_timeout` in `uplink.ml`) and must move together.
- **Request-body bytes are progress.** `Client.write_body` signals the stall detector per piece accepted by the socket, so a large upload on a slow link does not read as a stall (pitfall A-11.2).
- **Idle connections are kept 60 s, at most 32 per endpoint** (`idle_limit`, `max_connections`); a pooled connection that fails before any answer byte is redialled once, for every verb.
- **The probe is single-flight per store** (`Bucket_function.probe`): a second caller awaits the first one's `Rt.Promise`. The confirmation is a timestamp file written with `Fs.durable_replace`; `due` renews it a day before it lapses.
- **The function is Python**, not in this tree's OCaml: `lambda/verify.py` with `store_aws.py` and `store_gcs.py`, deployed by `terraform/`. It restates the key layout as constants. The chunk key is the one mechanical cross-check: `lambda/test_chunk_key.py` reads `tests/unit/hash/hash.expected` (pitfall A-7.5).

## S3 driver

### Map

| Spec (s3) | Code |
|---|---|
| Fields (§1) | `fields` in `s3.ml`; `valid_region`; `endpoint_url` (AWS by region, `.cn` for `cn-`, `https://` for a bare host); a path in `endpoint` is refused in `create` |
| Path-style addressing, key encoding (§2) | `path`, `S3.uri_encode ~keep_slash`, `S3.canonical_query` |
| SigV4 (§3.1) | `S3.authorization`, `S3.amz_date`; `call` signs inside `Client.request`'s `headers` thunk, so each attempt carries a fresh date |
| Payload hash (§3.2) | `put_request`: `Digestif.SHA256.digest_bigstring`, or `UNSIGNED-PAYLOAD` |
| Verbs (§4) | `put_request`, `put_if_absent`, `put_if_unchanged`, `get_opt`, `get_range`, `head_opt`, `present` and `delete`, `delete_page`, `copy` (`x-amz-copy-source`), `list_page` |
| Ignoring-provider checks (§4.2) | `check_claims`, `check_replaces`: `Unchecked \| Honoured \| Ignored` in an `Atomic`, `Honoured` from the start without `endpoint` |
| Checksums (§4.5) | `checksum`, `Checksum.md5_of_hex`, gated by `etagIsMd5` |
| Error mapping (§5) | `fail`: `Object_store.status_failure`, with the reasons for `RequestTimeTooSkewed` and the redirects, and the region from `x-amz-bucket-region` or the body |
| Registration | the top-level `Driver.register "s3"` |

### Departures

- **The signing key is derived on every request** (four HMACs), not cached per day.
- **A store whose claims were found ignored is still asked for an `If-Match` replace.** `put_if_unchanged` runs `check_claims` only for `expected = None`; with an etag it relies on `check_replaces` alone.

### Learnings

- **The driver has no S3 library.** Signing, XML and paging are about 500 lines over `Tsync_http.Client`, which gives S3 the same pool, redial, stall detector and TLS choice as GCS and the http-proxy client.
- **One string is signed and sent** (pitfall B-2.3). `call` builds `path` and the canonical query once and uses them for the request target and for `authorization`; `%` and `+` are escaped by `uri_encode` in both.
- **Every header sent is signed**, the host included: `authorization` takes the header list and sorts it, so adding a header to a request cannot leave it unsigned.
- **XML without a parser.** `Bucket_xml.elements` and `field` scan for tags; elements do not nest under the same tag in the answers read. `Bucket_xml.safe` sends a key XML 1.0 cannot carry to a single DELETE (pitfall B-2.6).
- **`delete` costs a HEAD and a DELETE** (finding 128), since S3's DELETE answers 204 either way. The HEAD is `present`, which reads the status only: a HEAD lacking a header an entry needs does not fail the delete.
- **A server-side copy can answer 200 with an `<Error>` body**; `copy` reads the code before it trusts the status.
- **A range answered 200 with a `Content-Range`** (rclone) is checked as a 206; a 200 without one is the whole object, CORRUPT when more than `len` bytes remain past the offset.
- **A provider that ignores `If-None-Match` cannot be told from one claim** (pitfall B-2.1). The checks rewrite the empty chunk with its own bytes, which is harmless either way; the verdict is kept for the store's life in this process.
- **`etagIsMd5: true` on a bucket whose ETags are not MD5s never yields a false equality**: `Checksum.md5_of_hex` takes exactly 32 hex digits, and a wrong value differs from a real MD5.
- **Tests.** `tests/store/s3_test` checks SigV4 vectors and `uri_encode`, runs the contract against a fake on loopback that verifies every signature, and against a real service when the `TSYNC_CI_S3_*` variables are set. The fake verifies with the driver's own canonicaliser (finding 159); a real run scopes its objects by `Contract.run_scope`.
