Notes specific to one driver are in [local](backends/local.md), [s3](backends/s3.md), [gcs](backends/gcs.md), [http-proxy](backends/http-proxy.md). Some of them are also summarised below from the first extraction.



## B.1 Runtime-independent OCaml learnings (valid under Lwt or OCaml 5 direct style)

- **Abstract key type with no `of_string`** (`Stored_key.t`) and an abstract `Watch_token.t`: the type system is what stops a raw string, an entry key or an etag from being passed where a stored key/token is expected (a watch comparing the wrong spelling held requests it should have answered). Keep these abstract (spec §2.1, §2.6).
- **First-class modules as the store value** (`(module Store)`): the composite and every driver are values of one module type, so the composite is itself a store and members can be stored in lists/records. An object or a record of closures would do equally well; what matters is one interface type for leaf and composite (spec §3.1).
- **Optional capabilities as `option` fields of functions** (`get_many`, `list_many`): the absence is in the type and the generic fallback (`Batched`) is written once (spec §7.1).
- **Admission as a record of closures**, not a functor argument: a store built once can take whichever gate config names (spec §4.9).
- **Bigstring bodies, never strings**: chunk bodies stay off the OCaml heap end to end — local reads `mmap` (`Bigstring.map_file`), s3 `put_bigstring`/`get_bigstring`, the proxy responds with `Body.of_bigstring (`Passthrough data)`, SHA-256 for the HMAC is computed with `digest_bigstring` rather than converting the body. Two consequences: (1) a body handed to a request must stay valid until it is answered, retries included (s3 comment); (2) mmapped bytes stay correct only because a name is *only ever replaced by rename*, never written through — any code path that opens a store file for writing in place would corrupt live mappings (spec §4.2 local).
- **Physical equality `held != data`** in the counting wrapper tells a claim's winner from its loser without comparing bodies (spec §6.1 item 9). Fragile if any layer copies the buffer on the win path.
- **mmap past EOF is SIGBUS, not a short read**: `get_range` clamps `len` to `size - offset` before mapping.
- **`Printexc.register_printer`** is needed for exceptions that reach users: the default printer spells the wrapped-library module path (`Tsync_backend_api.Backend.Not_writable`) (backend.ml).
- **32-bit overflow in frame decoding**: lengths are compared against the bytes remaining (`n > len - pos`) rather than `pos + n > len`, which overflows on 32-bit and would pass a negative length to `String.sub` (raising `Invalid_argument` instead of the promised `Failure`) (http_proxy.ml).
- **Dune layout**: the API library (`tsync_backend_api`) sees only core/io/uplink; drivers are separate libraries opened with `-open`; the s3 driver is `(optional)` and selected with `(select s3_link.ml from (tsync_s3_backend_lwt -> s3_link.enabled.ml) (-> s3_link.disabled.ml))`. Drivers register from their initialiser and are kept in the link by `(library_flags (-linkall))` — without it an unused driver module is dropped and its registration never runs, silently (a "select + linkall" build can stay green with a driver missing; test the registry's `types ()`). `gcs_auth` is a `private_modules`.
- **Crypto without an RNG**: GCS JWT signing uses `Mirage_crypto_pk.Rsa.PKCS1.sign ~mask:`No` because the key is used before any TLS connection exists to seed the RNG; PKCS#1 v1.5 is deterministic.
- **Date parsing without a dependency**: Hinnant's days-from-civil for GCS RFC 3339 `updated`.
- **Minimal hand-rolled XML** for GCS bulk delete (escape + scan for `<Error>`), and `Stdlib.Digest` (MD5) for `Content-MD5` — no XML dependency for one call.
- **Local walk memory**: a promise per directory entry kept the whole tree alive (≈100 MB of closures for 500k manifests); a fixed number of workers pulling from a shared list fixed it. Under direct style the same lesson applies to fibers: bound the number of live tasks, not just the number doing I/O.
- **The uplink modules are pure OCaml with a `now` argument**, testable without any scheduler; the stall timeout is a global `ref` read by the GCS driver so window and deadline cannot drift.

## B.2 Lwt / functor-specific learnings (and what they become under effects/domains)

- **Functor-over-concurrency-signature pattern**: every module is `Over (Io : Io.S) (Bounded) (Clock) (Lock) (Durable_queue) (Http_client) …` and is applied once in `lib/lwt/backends` (`Backend.Make (Io_lwt.Core) (Io_lwt.Bounded)`, `Domain_store.Over (Io_lwt.Core) (Durable_queue_lwt) (Io_lwt.Lock) (Io_lwt.Clock) (Backend_lwt)`, each driver's `*_lwt.ml`). It solved: no library below the app names Lwt; tests can use fakes (fake clock, stub stores). It cost: a mirror tree `lib/lwt/...`, functor-application boilerplate, and type-sharing constraints (`with type 'a io := 'a Io.t`; `S3io : Aws_s3.Types.Io with type 'a Deferred.t = 'a Io.t` pins aws-s3's own deferred to ours). Under OCaml 5 direct style the functor collapses to plain modules; keep only the *clock* and *filesystem* seams for tests.
- **Process-global registries force a single application**: `Backend.Make` holds the driver registry, drain hooks and batch pool; applying it twice would create two registries and drivers would register into one while the app reads the other. Same for `Domain_store`'s `hooked` flag and `Deferred`'s `resumed_starts`. Under direct style these are just globals — but with domains they need `Atomic`/`Mutex`.
- **Cooperative atomicity is load-bearing** (spec §6.1). In Lwt, code between binds is atomic; `Lwt.async f` runs `f` synchronously until its first bind, which is what lets `try_admit` → `acquire` hold. Under effects with a single-domain scheduler this still holds as long as nothing performs an effect in between; with multiple domains every item in §6.1 becomes a data race and needs a mutex or an atomic try-take.
- **`let*` marks every yield point**; the absence of a bind is how the code documents "no interleaving here" (gate `acquire` fast path returns `Io.return ()` without binding). Direct style loses that visual marker: comment or encapsulate those critical sections.
- **Pool nesting deadlock**: a caller holding a slot from pool P must not take a second slot from P (the composite forwards native batches directly instead of through `Batched`; the local walk holds its slot around the `stat` only). Becomes the same rule for semaphores in direct style.
- **Bounded fan-out**: `Bounded.map_with slots f list` rather than `Lwt_list.map_p`; `Io.iter_p` appears only where the width is fixed by code (four capability queries, drain hooks, 4096 verify PUTs under a 32-slot pool). Under effects, unbounded `Fiber.all` is the same bug.
- **Cancellation**: `Clock.pick`/`with_timeout` cancel the losing branch (`Health_wait.until_held`); the retry loop must not retry a cancellation (`Clock.is_cancelled`), and a probe cancelled by its deadline tells the health cell nothing, hence `Health.probe_lost`. Under effects, cancellation must be explicit (a switch/cancel context); the same rule — never retry a cancelled request, and record the probe's deadline as a failure — carries over.
- **`Lwt.async` exceptions**: frontends set `Lwt.async_exception_hook` to log, because the default kills the process on any escaped exception from a background loop (watch loops, chunk forwards). Chunk forwards and watch loops catch everything themselves.
- **Lwt_condition + `Lwt.pick [wait; sleep]`** implements the proxy's per-key long poll; the loop runs only while waiters exist.
- **Wake order**: gates use `Io.wakeup_later` so a woken waiter does not run inside `pump` while the queue is being iterated.
- **Fork discipline**: stores (and resumable queues) are built before the daemon forks its frontends; queues are started only in the parent afterwards (`start_resumed`), and Lwt-using setup in children happens after the fork ("the first thing to touch Lwt"). Under OCaml 5, `Unix.fork` is refused once a second domain has been spawned — fork before spawning domains, or move frontends to separate exec'd processes.
